# HDMI rollout optimization decisions — 2026-09-22

## Retained scope

The approved change retains only steps 1–4 of the rollout bar plot:

1. Cache HDMI object indices on GPU (already committed in HDMI `0c21416`).
2. Cache Mimic-Lite motion body/joint indices on GPU. HDMI refreshes those caches after extending the tracking selection with object indices.
3. For all-full/resident motion datasets, read through fixed-shape GPU index tables instead of dynamically partitioning requests. This does not change full/windowed loading, motion contents, sampling, or reset behavior. Mixed resident/windowed datasets retain their original route.
4. Select quaternion candidates using fixed-shape `gather` instead of boolean indexing.

NaN-guard behavior, reset-mask/ID handling, primers, dataset sampling groups, rewind branching, and reset state clearing are restored to their pre-experiment implementations. No MjLab or upstream TorchRL changes are included. Earlier observations/rewards/NaN-guard compilation already in HEAD remains unchanged.

## Findings retained from discarded experiments

- Redundant reset synchronization calls fell from 2016 to 640 per traced 32 steps, without a corresponding large throughput gain. Stackful trace durations cannot be compared directly with stackless traces.
- Fixed-shape masked reset is feasible for environment bookkeeping, but existing motion/scene/callback consumers still require environment IDs. The final environment-only mask bridge was correctness-tested but not throughput-tested; it has now also been discarded.
- Disabling terminations with a random initial policy produced contact/constraint overflow and non-finite state after 33 steps. Those timings are invalid.
- A separate frozen-checkpoint diagnostic used 1024 environments, NaN guard off, increased contact/constraint capacity, and no PPO updates. It verified zero resets and finite robot joints/root state. Retaining the done check produced 32 synchronizations per 32 ordinary steps; bypassing it produced zero in a no-push window. CUDA-event rollout elapsed time was 0.789777 vs 0.770598 seconds. These timings are not comparable to the 8192-env PPO rows above.
- A longer no-reset/no-check trace covered 352 steps and found 249 synchronizations, all from the periodic push CPU-to-GPU index transfer. Boundary finite-state checks were outside the measured rollout scope. Kernel launch fragmentation remained even in ordinary steps with zero explicit synchronization.
- Branchless NaN sanitization regressed rollout from 1.7455 to 1.7675 seconds; a counter-only diagnostic change measured 1.8323 seconds. Both were reverted.
- Independent policy compilation measured 1.678 seconds rollout and 3.996 seconds rollout plus PPO, with increased startup cost. It remains an existing opt-in option, not part of this change.

The formal 8-card training used its frozen source and was not changed by these experiments. Detailed local artifacts, raw summaries, plots, and discarded source patches are under workspace `tasks/hdmi-local-object-20260922/`; remote raw profiles are under `/data/elijah/hdmi-rollout-opt-20260922/` on rp-4090-6.
